# PDPA → กฎที่ระบบต้องบังคับ

> สรุปเพื่อใช้ออกแบบและทดสอบระบบ **ไม่ใช่คำปรึกษาทางกฎหมาย** · อ้างอิง พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (เรียก ม.xx) และประกาศคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) ตามรายการท้ายไฟล์  
> ตัวบทและประกาศอาจเปลี่ยน — ฝ่ายกฎหมายตรวจอีกครั้งก่อน go-live ทุก phase (T30, T37) · ข้อความทางกฎหมายที่ระบบสร้าง (ประกาศ แบบแจ้ง สัญญา) ต้องผ่าน legal review ก่อนเผยแพร่เสมอ

## วิธีใช้ไฟล์นี้

- ทุกแถวคือ **กฎที่ต้องมี test** (unit หรือ integration) — ตั้งชื่อ test ให้ค้นเจอด้วยมาตรา เช่น `TestConsent_Sec19_NoPreTickedPurpose`
- คอลัมน์ “ที่ implement” ชี้ไป module / ตาราง / process / state machine ในชุดเอกสารนี้
- ถ้าต้องตีความกฎหมายเพิ่มจากที่เขียนไว้ **ให้หยุดและถาม** (บันทึกใน `docs/decisions.md`) อย่าเดาเอง

| ข้อมูลจราจรทางคอมพิวเตอร์ของระบบ เก็บอย่างน้อย 90 วัน | พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ ม.26 (กรณีเป็นผู้ให้บริการ) | retention ของ `platform.audit_log` = 5 ปี ([decisions D-22](../decisions.md), job `audit.retention`) · `iam.security_events`, access log ยังไม่กำหนด |

นับเวลาเป็น UTC ในฐานข้อมูล แสดงผล Asia/Bangkok · ใช้ clock ที่ inject ได้เพื่อทดสอบ · ระยะเวลาที่เป็น “วัน” ใช้วันตามปฏิทินเป็นค่าเริ่มต้น การนับวันทำการ / การหยุดนับ SLA ระหว่างรอข้อมูลต้องตั้งค่าได้ต่อประเภทคำขอ (ยังเปิดอยู่ใน `docs/decisions.md`)
